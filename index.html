0 · How the wiki is organised

Two axes. The first is the asset class (residential fix-and-flip and development, or offices). The second is the role of the page: a deal model, a programme or investor page, a market piece, or a corporate hub. Each page gets one card with the same fields, so the whole estate can be scanned in one pass.

Fields on every card

  • Live URL with copy button; repo / file as it sits on GitHub.
  • Dates: first commit → last commit, and the version label the page itself carries.
  • Visibility: listed = linked from a hub or data room; unlisted = hash-named file shared only by direct link; orphan = nothing links to it.
  • Key figures as the page computes them on load (base case).

Conventions on GitHub

  • URL pattern https://egasnikov.github.io/<repo>/ serves index.html; other files by name.
  • One repo per asset since July (al-barari-type-b, sienna-lakes, leaf-tower...). Earlier work is grouped by theme (flipping, sky-tower, adgm-flex-office).
  • palm-peak is the public hub and also hosts unlisted models (hash filenames) so they don't appear on the hub.
  • Free-plan Pages are public: anything with a URL is readable by anyone who has it. All pages carry "illustrative, not an offer".
